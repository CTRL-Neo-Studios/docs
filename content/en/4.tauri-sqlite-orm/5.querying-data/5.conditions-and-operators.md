---
title: Conditions & Operators
description: Using Conditions & Operators in Tauri SQLite ORM.
---

Condition operators are the functions you use to build filtering logic for your queries. They are passed to the
`.where()` clause of `select`, `update`, and `delete` statements to create powerful, type-safe SQL conditions. Each
operator function returns a special `{ sql, params }` object that the query builder uses to safely construct the final
query.

All operators are imported from the root of the `@type32/tauri-sqlite-orm` package.

```ts
import {eq, and, or, not, like, inArray /* etc. */} from '@type32/tauri-sqlite-orm';
```

## Logical Operators

These operators are used to combine multiple conditions.

| Operator                 | Description                                        | Example Usage                                                      |
|--------------------------|----------------------------------------------------|--------------------------------------------------------------------|
| **`and(...conditions)`** | Combines multiple conditions with a logical `AND`. | `where(and(eq(users.status, 'active'), gt(users.loginCount, 10)))` |
| **`or(...conditions)`**  | Combines multiple conditions with a logical `OR`.  | `where(or(eq(users.role, 'admin'), eq(users.role, 'owner')))`      |
| **`not(condition)`**     | Negates a single condition.                        | `where(not(eq(users.status, 'banned')))`                           |

## Comparison Operators

These operators compare a column's value to a provided value.

| Operator                        | Description                                                                                                        | Example Usage                      |
|---------------------------------|--------------------------------------------------------------------------------------------------------------------|------------------------------------|
| **`eq(column, value, alias?)`** | Equal (`=`). The optional third argument is for table aliases, useful in [Joins](../6.advanced-topics/2.joins.md). | `where(eq(users.id, 1))`           |
| **`gt(column, value)`**         | Greater than (`>`).                                                                                                | `where(gt(posts.viewCount, 1000))` |
| **`gte(column, value)`**        | Greater than or equal to (`>=`).                                                                                   | `where(gte(users.age, 21))`        |
| **`lt(column, value)`**         | Less than (`<`).                                                                                                   | `where(lt(products.stock, 5))`     |
| **`lte(column, value)`**        | Less than or equal to (`<=`).                                                                                      | `where(lte(tasks.priority, 2))`    |

## Value Checking Operators

These operators are used for pattern matching, list containment, and `NULL` checks.

| Operator                      | Description                                                        | Example Usage                                            |
|-------------------------------|--------------------------------------------------------------------|----------------------------------------------------------|
| **`like(column, pattern)`**   | String pattern matching (`LIKE`). Use `%` as a wildcard character. | `where(like(users.email, '%@domain.com'))`               |
| **`inArray(column, values)`** | Checks if a column's value is within an array of values (`IN`).    | `where(inArray(users.status, ['pending', 'reviewing']))` |
| **`isNull(column)`**          | Checks if a column's value is `NULL`.                              | `where(isNull(posts.publishedAt))`                       |
| **`isNotNull(column)`**       | Checks if a column's value is `NOT NULL`.                          | `where(isNotNull(posts.publishedAt))`                    |

## Combining Operators

The real power comes from composing these operators to create complex queries. Since `and()` and `or()` accept multiple
conditions, you can nest them to build precise filtering logic.

```ts
import {db} from '$lib/db';
import {users, posts} from '$lib/db/schema';
import {and, or, eq, isNull, gte} from '@type32/tauri-sqlite-orm';

// Find all posts that are either unpublished OR have more than 100 likes
const popularOrUnpublishedPosts = await db.select(posts)
    .where(
        or(
            isNull(posts.publishedAt),
            gte(posts.likeCount, 100)
        )
    )
    .all();

// Find all active admin users
const activeAdmins = await db.select(users)
    .where(
        and(
            eq(users.status, 'active'),
            eq(users.role, 'admin')
        )
    )
    .all();
```
